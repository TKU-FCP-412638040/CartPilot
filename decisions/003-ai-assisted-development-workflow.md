# 決策卡 3：AI 協作開發工作流

- 問題：如何讓 AI 加速從需求到 PR 的交付，同時保留可理解、可驗證與安全的品質門檻？
- 選項：依賴提示詞臨場操作；導入完整 Jira / CI / Hooks / MCP 自動化；先以 repo 規格、指引和 PR 驗證流程建立最小閉環
- 取捨：臨場操作啟動快，但脈絡與驗證容易遺失；完整自動化可省人工，但目前 repo 未有整合設定，權限、憑證與維運成本未知；repo 內流程可先建立一致做法，並為後續工具接入留下明確界線
- 選擇與理由：先採用 repo 內規格、`AGENTS.md`、工作流程 Skill 與 PR 範本，使用現有 lint/build 命令驗證。AI 可準備提交資料，但外部寫入操作須由人確認；不設定自動合併。此做法符合先規格、重要決策留痕、資料操作需確認及測試通過才合併的原則。
- 何時會改：當 Jira、CI 與評估執行器完成設定，且權限、失敗處理、人工核准與維護責任都有明確方案時，再新增對應自動化決策卡。
